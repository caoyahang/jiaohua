# 操作手册

> 依据《AI焦化厂智能化落地方案 V1.1》第七章（分阶段实施路线）与第十三章（成功关键因素 Checklist）整理。
> 面向运维/值班工程师：按阶段给出任务要点、验收标准与日常运维关注点。

## 1. 日常运维通用要点

- **数据底座优先**：一切 AI 应用依赖数据在线率 ≥ 99%、延迟 ≤ 5 秒。每日检查采集服务状态与点位失败数（Grafana「数据底座监控」仪表盘）。
- **换向期脏数据**：换向前后 2~3 分钟的温度/流量/吸力由 ETL 自动打标记剔除；若发现标记异常增多，先查 DCS 换向信号点位。
- **安全红线（不可妥协）**：安全联锁永远走 DCS 硬联锁回路；AI 只输出设定值且 DCS 侧硬钳位；
  「一键切手动」为硬切换，不经过 AI 软件层。任何 AI 侧异常，先切手动再排查。
- **AI 服务宕机预案**：DCS 自动保持最后有效设定值并报警，不依赖 AI 心跳；恢复后检查设定值是否需人工复位。
- **模型版本**：所有模型经 MLflow 注册管理，回滚时切换模型版本即可，禁止手工替换模型文件。

## 2. 分阶段任务与验收（V1.1 第7章）

### 阶段一：数据底座建设（第1~2月）

- [ ] 部署 Docker 环境（Ubuntu + Docker Compose）
- [ ] 部署 TDengine 集群（2节点主从）、PostgreSQL（主从复制）、Redis
- [ ] 编写 OPC UA 采集脚本（Python asyncua）
- [ ] 对接 DCS 测试环境，验证数据采集（先采 5~10 个关键标签）
- [ ] 编写数据质量校验模块（范围检查、缺失插值、突变告警）
- [ ] 建立数据库表结构（配煤、化验、炉温、设备）
- [ ] 部署 MLflow、FastAPI 基础框架（用户认证、日志、健康检查）

**验收**：关键标签采集延迟 ≤ 5秒；数据在线率 ≥ 99%；表结构通过评审；MLflow 可正常记录实验。

### 阶段二：焦炭质量预测模型（第2~3月）

- [ ] 实现经验配煤模型（CBRI法/煤岩配煤法）作为冷启动"模型A"
- [ ] 建立拟采购煤种数据库（20~30 个煤种全分析 + 煤岩反射率分布）
- [ ] 40kg/200kg 试验焦炉 DOE 试验（≥60 炉，覆盖主要煤种组合），标定小焦炉与大炉 CSR/CRI 系统偏差
- [ ] 特征工程（约 40 维，含炼焦工艺侧）
- [ ] LightGBM 四指标模型训练（M25/M10/CSR/CRI）+ 模型评估（R²/MAE/交叉验证）+ SHAP 分析
- [ ] 封装为 FastAPI 服务；前端页面：输入配煤比 → 显示预测质量
- [ ] 给配煤师演示，收集反馈

**验收**：经验模型 + DOE 数据跑通全流程；DOE 数据集 R² ≥ 0.75（本厂数据积累后提至 ≥ 0.80）；
预测响应 < 1秒；SHAP 图可展示；配煤师能独立操作。

### 阶段三：智能配煤优化器（第3~4月）

- [ ] 接入实时煤价（ERP/手动录入）与库存数据
- [ ] 遗传算法优化器（scikit-opt），多目标三套方案（成本最优/质量最稳/综合推荐）
- [ ] 约束处理（配比上下限、库存约束、质量下限）
- [ ] 前端交互：输入目标质量 → AI 返回 3 套方案 → 人工确认
- [ ] 配煤方案执行记录回写数据库；第一笔真实配煤方案投产验证

**验收**：求解 < 5秒；三套方案差异明确；确认流程完整；执行结果可追踪。

### 阶段四：焦炉AI加热控制（第4~6月）

- [ ] 采集火道温度、煤气流量等时序数据（积累 ≥2 月）
- [ ] 数据清洗与特征工程（含换向期剔除）
- [ ] LSTM 温度预测模型训练；MPC 控制器（Python 原型）+ 粒子群求解器
- [ ] 部署为 FastAPI 服务
- [ ] **影子模式连续运行 3 个月**，记录 AI vs 人工对比数据
- [ ] 验证通过后切换半自动（AI建议+人工确认）→ 最终全自动（保留一键切手动）

**验收**：影子模式 3 个月，AI 温控误差 < 人工误差；煤气消耗对比基线降 ≥ 2%；一键切手动正常；调火工培训完成。

### 阶段五：设备PdM + 安全视觉（第5~6月）

- [ ] 振动传感器选型安装（P0 设备优先），振动数据接入 TDengine
- [ ] 孤立森林异常检测 + LSTM 趋势预测 + 健康评分模型
- [ ] 告警推送前端 + 企业微信/钉钉
- [ ] 摄像头部署（炉顶/地下室/皮带走廊/煤气柜），YOLOv8 训练（安全帽/烟火/闯入）
- [ ] 视频流拉取 + 推理 + 告警；红外热成像接入（煤气泄漏）

**验收**：P0 覆盖率 100%；异常检测准确率 > 85%（前3个月允许偏低）；视觉识别准确率 > 90%；告警响应 < 5秒。

### 阶段六：排产优化 + 领导驾驶舱（第6~8月）

- [ ] APS 排产模型（OR-Tools CP-SAT），对接订单/高炉需求，自动生成推焦计划
- [ ] K3 系数自动计算与优化
- [ ] 领导驾驶舱（ECharts 平面大屏，信息密度高、维护成本低）
- [ ] ~~3D数字孪生~~（后置/可选，确有需要再外包）
- [ ] 移动端适配（关键告警查看）

**验收**：排产方案可执行率 ≥ 95%；驾驶舱刷新延迟 < 10秒；移动端可查看关键告警。

### 阶段七：闭环迭代 + 持续进化（第8~12月）

- [ ] 所有模型接入自动重训管道；模型漂移检测（Prometheus + 自定义指标）
- [ ] A/B 测试框架（新模型 vs 旧模型）；数据回流自动化
- [ ] 模型版本管理（MLflow）；月度性能评估报告
- [ ] 化产数据积累 ≥3 个月后启动二期化产回收 AI 优化
- [ ] 探索：焦炉煤气制氢产线 AI 优化、碳管理模块

## 3. 成功关键因素 Checklist（V1.1 第13章）

### 3.1 技术侧

- [ ] DCS 接口在设计阶段就锁定（OPC UA 强制条款 + 点表交付 + LIMS 电子接口）
- [ ] 数据底座先于一切 AI 应用建成
- [ ] 模型可解释（SHAP/LIME），不让黑箱决策
- [ ] 所有 AI 控制保留人工接管能力
- [ ] 安全联锁永远走 DCS 硬回路，AI 只输出设定值且 DCS 侧硬钳位（红线，不可妥协）
- [ ] 配煤冷启动用经验模型 + 试验焦炉 DOE，不赌"买同行数据"
- [ ] 质量预测特征必须含炼焦工艺侧（结焦时间/火温/堆密度/熄焦方式）
- [ ] 模型版本管理 + 自动重训管道

### 3.2 管理侧

- [ ] 厂里一把手明确支持 AI 项目
- [ ] 配煤师/调火工参与模型设计（不是被动接受）
- [ ] 第一版配煤工具足够简单（5 分钟上手）
- [ ] 用实际省钱效果争取后续投入
- [ ] 建立"AI建议 + 人工确认"的信任过渡期

### 3.3 商务侧

- [ ] 核心算法和代码归属厂方（合同明确）
- [ ] 数据所有权归厂方（不共享给外部）
- [ ] 分期验收 + 阶梯付费（不一次性付全款）
- [ ] 关键岗位做好知识备份

## 4. 常见告警处置速查

| 告警 | 首要动作 | 后续排查 |
|---|---|---|
| 集气管压力高限 | DCS 硬联锁自动动作；调火工现场确认 | 查鼓冷系统、集气管调节阀 |
| AI 加热控制异常 | 一键切手动（硬切换） | 查 AI 服务日志、LSTM 输入数据质量 |
| 采集延迟 > 5秒 | 查采集服务与 OPC UA 连接 | 网络/交换机、DCS 负载 |
| PdM DANGER（振动 > 18 mm/s） | 立即停机检查（ISO 10816） | 轴承/对中/基础松动 |
| 质量预测误差持续超限 | 通知算法工程师 | 触发增量训练；检查煤源是否变化（漂移） |
