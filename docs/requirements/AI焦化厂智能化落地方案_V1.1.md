## 一、项目背景与目标

### 1.1 背景

焦化行业正经历"智能化"转型窗口期。政策端（超低排放、碳市场）、市场端（煤价波动、利润压缩）、技术端（AI/大数据成熟）三重压力叠加，传统"经验驱动"管理模式已触天花板。新建焦化厂具备"一张白纸"优势，可从设计阶段原生集成AI能力，避免老厂改造的兼容性与数据孤岛问题。

### 1.2 总体目标

| 维度 | 目标（达产后12个月） |
|---|---|
| 配煤成本 | 吨焦配煤成本降低 **5~20元** |
| 焦炭质量 | 质量预测准确率 **≥ 90%** |
| 焦炉能耗 | 加热煤气消耗降低 **≥ 2.5%** |
| 设备可靠性 | 非计划停机减少 **≥ 30%** |
| 安全管理 | AI识别覆盖率 **100%**，响应 **< 5秒** |
| 数据资产 | 全厂数据在线率 **≥ 99%**，延迟 **≤ 5秒** |

### 1.3 核心原则

1. **厂方主导，不依赖厂商绑架**——模型、数据、代码归自己所有
2. **先辅助后闭环**——AI建议 → 人工确认 → 影子模式 → 逐步闭环
3. **简单模型优先**——LightGBM/XGBoost 打底，深度学习攻坚
4. **数据底座先行**——设计阶段锁定采集接口，杜绝事后补课
5. **人在回路**——老师傅经验反哺模型，模型结果可解释

## 四、AI应用系统详细设计

### 4.1 应用一：智能配煤系统（第一批上线，ROI最高）

#### 4.1.1 系统定位

**目标**：输入焦炭质量要求和当前煤种库存/价格 → 输出3套配煤方案（成本最优/质量最稳/综合推荐）→ 配煤师确认 → 执行 → 结果回流 → 模型自学习。

#### 4.1.2 三模型协同架构

```
┌──────────────────────────────────────────────────────────┐
│                    智能配煤引擎                           │
├──────────────────────────────────────────────────────────┤
│  模型A：焦炭质量预测模型 (LightGBM)                      │
│  输入：配煤方案 → 输出：M25/M10/CSR/CRI预测值             │
│  作用：作为优化器的"模拟器"（代理模型）                    │
├──────────────────────────────────────────────────────────┤
│  模型B：配煤成本优化器 (遗传算法 GA)                      │
│  输入：煤种/价格/库存/质量约束 → 输出：最优配比            │
│  调用模型A作为适应度函数                                  │
├──────────────────────────────────────────────────────────┤
│  模型C：煤质-成本弹性分析 (SHAP可解释性)                  │
│  输入：当前最优解 → 输出：各煤种对成本/质量的边际贡献      │
│  作用：辅助配煤师理解和微调                                │
└──────────────────────────────────────────────────────────┘
```

#### 4.1.3 核心算法选型

| 环节 | 算法 | 理由 |
|---|---|---|
| 质量预测 | 冷启动：**经验配煤模型**（CBRI法/新日铁配煤法/煤岩配煤模型）；数据积累后：**LightGBM** / XGBoost | 新厂无历史数据，先用公开经验公式跑通流程；GBDT是表格数据王者、可解释、训练快、支持增量学习 |
| 配煤优化 | **遗传算法**（scikit-opt） | 处理非线性约束、多目标优化能力强 |
| 可解释性 | **SHAP值分析** | 告诉配煤师"为什么是这个配比" |
| 小样本期 | **高斯过程回归（GPR）** | 数据少时也能给出置信区间 |

#### 4.1.4 特征工程清单（约40维特征，V1.1修订）

**单种煤基础指标（7维+分布特征）**
- 灰分(Ad)、挥发分(Vdaf)、硫分(St,d)、粘结指数(G)、胶质层厚度(Y)
- 镜质组反射率**分布直方图**（Rmax 0.5~2.0分段占比，8~12维）——⚠️ V1.1修正：单值Rmax表达不了混配后反射率分布的"凹口"（配煤大忌），必须用分布特征；化验室需配煤岩分析仪或外送检测
- 活惰比（活性物/惰性物，煤岩定量）

**配比特征（5维）**
- 各煤种配比、配比熵（衡量配比分散度）、最大单一煤种占比、最低占比煤种、配比方差

**成本特征（3维）**
- 吨煤成本、各煤种单价、价格波动率（近30天）

**煤岩组合特征（5维）**
- 活性物/惰性物含量（煤岩定量实测，非估算）、活惰比、流动性指数(G×Y/Ad)、镜质组丰度、壳质组含量

**工艺特征（4维）**
- 装炉煤堆密度、水分(Mt)、粉碎细度(<3mm占比)、配合煤CSR预估值

**炼焦工艺特征（5维，V1.1新增）**
- 实际结焦时间、机侧/焦侧平均火道温度、装炉堆密度实测值、熄焦方式（干熄/湿熄）、干熄率
- ⚠️ 焦炭CSR/CRI同时强依赖炼焦工艺：同一配煤比，结焦时间20h→24h，CSR可差3~5个点。只喂煤质特征会把工艺波动全部学成噪声，R²天花板受限

**约束特征（4维）**
- 各煤种库存可用天数、供应商最低采购量、运输在途量、合同锁价量

#### 4.1.7 增量学习机制（关键）

```python
# 模型不是训一次就完了，要建立自动闭环
# 每次出焦化验结果回来 → 对比预测值 → 误差超过阈值 → 触发微调

class IncrementalLearner:
    def __init__(self, model_path):
        self.model = load_model(model_path)
        self.error_buffer = []
        
    def on_new_coke_data(self, blend_features, actual_quality):
        # 1. 用当前模型预测
        pred = self.model.predict(blend_features)
        
        # 2. 计算误差
        error = abs(pred - actual_quality)
        
        # 3. 误差超限 → 加入缓冲区
        if error > THRESHOLD:
            self.error_buffer.append({
                'features': blend_features,
                'actual': actual_quality,
                'pred': pred,
                'error': error
            })
        
        # 4. 缓冲区满50条 → 增量训练
        if len(self.error_buffer) >= 50:
            self._incremental_train()
            self.error_buffer = []
    
    def _incremental_train(self):
        # 用新数据微调最后几棵树
        new_df = pd.DataFrame(self.error_buffer)
        self.model.fit(new_df['features'], new_df['actual'], 
                      init_model=self.model,  # LightGBM支持热启动
                      learning_rate=0.01)     # 小学习率防遗忘
```

### 4.2 应用二：焦炉AI智能加热控制

#### 4.2.1 系统定位

**目标**：基于火道温度、煤气流量、烟气残氧等实时数据 → AI预测未来温度趋势 → 自动计算最优煤气流量/空气量设定值 → 下发DCS执行（或人工确认模式）。

#### 4.2.2 三阶段控制模式

| 模式 | 说明 | 适用阶段 |
|---|---|---|
| **Manual（手动）** | 完全人工控制，DCS自主操作 | 烘炉期、异常工况 |
| **Shadow（影子）** | AI实时计算但不下发，仅显示推荐值，与人工操作对比 | 试生产前3个月 |
| **Auto（自动）** | AI计算结果自动下发DCS执行，人工可一键切回手动 | 验证通过后 |

#### 4.2.3 算法选型

| 环节 | 算法 | 理由 |
|---|---|---|
| 火道温度预测 | **LSTM / Transformer** | 时序依赖强，需记忆长期趋势 |
| 火落时间预测 | **CNN + LSTM（时空特征）** | 结合看火孔图像+温度曲线 |
| 最优控制量求解 | **模型预测控制（MPC）** | 工业控制标准方法，有约束处理能力 |
| 超参数优化 | **贝叶斯优化** | 自动调参，减少人工干预 |
| 异常检测 | **自编码器（AutoEncoder）** | 无监督，发现未知故障模式 |

#### 4.2.4 控制架构

```
┌─────────────────────────────────────────────────────────┐
│                   MPC 模型预测控制                       │
├─────────────────────────────────────────────────────────┤
│  步骤1：状态预估                                         │
│  输入(过去60min)：火道温度序列、煤气流量、吸力、残氧      │
│  模型：LSTM温度预测器 → 预估未来30min温度曲线             │
├─────────────────────────────────────────────────────────┤
│  步骤2：优化求解（每2个交换周期执行一次）                 │
│  目标：min Σ(预测温度 - 目标温度)² + λ·煤气消耗量         │
│  约束：温度上下限、煤气流量限值、吸力限值                 │
│  求解器：粒子群优化(PSO) / 梯度下降                      │
├─────────────────────────────────────────────────────────┤
│  步骤3：下发执行                                         │
│  输出：煤气流量设定值 → DCS → 执行器                     │
│        分烟道吸力设定值 → DCS → 执行器                   │
│        空气过剩系数建议值（供调火工参考）                  │
├─────────────────────────────────────────────────────────┤
│  步骤4：反馈校正                                         │
│  实际温度 vs 预测温度 → 模型误差补偿 → 下次预测修正       │
└─────────────────────────────────────────────────────────┘
```

#### 4.2.5 关键参数采集清单

| 参数 | 位置 | 传感器类型 | 采样频率 | 用途 |
|---|---|---|---|---|
| 火道温度 | 每个燃烧室机/焦侧 | 热电偶/红外测温 | 1min | 核心控制变量 |
| 煤气流量 | 机焦侧横管 | 孔板流量计+差压变送器 | 30s | 控制执行变量 |
| 分烟道吸力 | 机焦侧分烟道 | 压力变送器 | 30s | 控制执行变量 |
| 集气管压力 | 机焦侧集气管 | 压力变送器 | 10s | 安全约束 |
| 烟气残氧 | 总烟道 | 氧化锆分析仪 | 1min | 燃烧效率优化 |
| 煤气热值 | 焦炉煤气管道 | 热值仪（可选） | 5min | 热值波动补偿 |
| 看火孔火焰 | 每个燃烧室 | 工业摄像头(防爆) | 5min | 火落判断辅助 |
| 环境温度 | 炉顶 | 温湿度传感器 | 5min | 环境补偿 |

#### 4.2.6 安全设计与热工K系数（V1.1新增）

**安全联锁硬隔离（红线，同步写入第九章DCS招标条款）**
- 集气管压力高限、煤气压力低限、烟道吸力低限等安全联锁**永远走DCS硬联锁回路**，AI通道物理上无权触碰
- AI只输出设定值（setpoint）；设定值的上下限与变化速率在**DCS侧硬钳位**，不依赖AI自律
- AI服务宕机/网络中断时，DCS自动保持最后有效设定值并报警，不依赖AI心跳
- 「一键切手动」为硬切换，不经过AI系统软件层

**换向期数据剔除**
- 换向前后2~3分钟的温度/流量/吸力数据为脏数据：入库前打标记、建模前剔除。这是焦炉时序数据清洗的第一课，必须在ETL管道中实现（见数据底座质量校验模块）

**热工K系数定义（驾驶舱与加热控制的统一考核口径）**

| 系数 | 定义 | 用途 |
|---|---|---|
| K均 | 直行温度均匀系数 =（机侧+焦侧合格火道数）/ 总测量火道数 | 加热控制核心KPI（对应10.1"温度均匀系数"） |
| K安 | 直行温度安定系数（相邻班次标准温度波动合格率） | 热工稳定性考核 |
| K1 | 推焦计划系数（计划结焦时间与规定结焦时间符合率） | 排产计划质量 |
| K2 | 推焦执行系数（实际推焦时间与计划时间符合率） | 执行质量 |
| K3 | = K1 × K2，推焦总系数 | 排产核心KPI（见4.5） |

> 数据来源：直行温度测量记录、推焦电流记录、推焦计划表——依赖数据底座先行落地。

#### 4.3.2 算法方案

```python
# 两级预警体系（V1.1修订：RUL后置）
# ⚠️ 焦化厂故障样本极少（单台设备年故障个位数），
#    LSTM退化模型/RUL在2~3年内没有足够样本训练，不做承诺式开发。
class PdMModel:
    """设备预测性维护模型（务实版）"""
    
    def __init__(self):
        self.models = {
            'isolation_forest': None,  # 异常检测
            'lstm_forecast': None,     # 趋势预测
        }
    
    def level1_realtime_alarm(self, sensor_data):
        """第一级：实时异常检测（毫秒级）"""
        # 孤立森林：发现突发异常（如振动突然飙升）
        score = self.models['isolation_forest'].predict(sensor_data)
        if score < -0.5:  # 异常
            return {'level': 'WARNING', 'msg': '振动异常，建议检查'}
        return None
    
    def level2_trend_forecast(self, history_7d):
        """第二级：趋势预测 + ISO 10816分级（每天跑一次）"""
        # LSTM：预测未来7天振动趋势，结合振动分级阈值判定
        trend = self.models['lstm_forecast'].predict(history_7d)
        if trend[-1] > THRESHOLD_CRITICAL:
            return {'level': 'DANGER', 'msg': '振动进入"危险"区，建议尽快停机检查'}
        elif trend[-1] > THRESHOLD_WARNING:
            return {'level': 'WARNING', 'msg': '劣化趋势明显，建议安排检修'}
        return None

# 后置项（积累2~3年故障样本后再立项）：
#   level3 RUL剩余寿命估算（LSTM+贝叶斯 / Wiener退化过程）
#   ——届时需先盘点有效故障样本量，≥50例再启动建模
```

| 振动速度(mm/s) | 等级 | 建议动作 |
|---|---|---|
| < 2.8 | 良好 | 正常运行 |
| 2.8 ~ 7.1 | 注意 | 加强监测频率 |
| 7.1 ~ 18 | 不合格 | 计划检修 |
| > 18 | 危险 | 立即停机 |

        schedule = self._solve_with_constraints(

### 5.2 算法选型决策树

```
数据是什么类型？
├─ 表格数据（配煤、化验、成本）
│   ├─ 数据量 < 200条 → 高斯过程回归(GPR) / 贝叶斯

│   └─ 数据量 > 10000条 → LightGBM + 特征选择

│   ├─ 目标检测(人/火/烟) → YOLOv8
│   ├─ 像素分割(块度/泄漏) → Mask R-CNN
│   ├─ 表计读数 → YOLOv8 + OCR
│   └─ 火焰分析 → ResNet + 分类头
│
└─ 优化决策问题
    ├─ 连续变量优化(配比/流量) → 遗传算法/粒子群
    ├─ 离散调度问题(排产/路径) → CP-SAT / 遗传算法
    └─ 多目标权衡(成本vs质量) → NSGA-II / 帕累托优化
```

### 5.3 为什么不推荐某些"热门"算法

| 不推荐算法 | 原因 | 替代方案 |
|---|---|---|
| 大模型(LLM/ChatGPT) | 焦化是数值控制场景，LLM擅长语言不擅长精确回归；数据敏感不能上云；推理成本高 | 规则引擎+知识图谱(设备说明书查询) |
| 深度神经网络(DNN) | 表格数据上不如GBDT，调参难，解释性差 | LightGBM + SHAP |
| SVM | 大数据量训练极慢，效果不如GBDT | LightGBM |
| 强化学习(RL) | 需要大量试错，焦化容错率低，烧坏炉砖代价巨大 | 先建数字孪生再考虑 |
| GAN | 工业场景数据增强收益有限，训练不稳定 | 传统数据增强+迁移学习 |

## 十五、总结

本方案的核心逻辑：

```
数据底座（必须） → 质量预测（最先出效果） → 配煤优化（最能省钱）
                → 加热控制（节能最大） → 设备PdM（防停机）
                → 安全视觉（合规刚需） → 排产+驾驶舱（全局管控）
```

**三个关键认知**：
1. **数据 > 算法**——花在数据采集和清洗上的精力应该占60%，模型本身只占20%
2. **简单 > 复杂**——LightGBM能解决的问题绝不上深度学习，可解释性就是生产力
3. **信任 > 精度**——AI准确率95%但老师傅不信，等于0；准确率85%但每步可解释，反而能落地

**你的独特优势**：市面上的AI公司不懂焦化工艺，焦化厂不懂AI技术。你两者都懂，这意味着你可以**用最小的成本、做最贴合实际的东西**，不需要被厂商忽悠买一堆用不上的"智慧平台"。
