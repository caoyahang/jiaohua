# 数据接口规范

> 摘录自《AI焦化厂智能化落地方案 V1.1》第 3.2 / 3.3 节与第 9.1 节。
> 用途：写入 DCS/MES 招标书及合同附件；数据底座采集开发的接口依据。

## 1. 必须开放的接口（V1.1 §3.2.1）

| 系统 | 协议 | 关键数据点 | 采集频率 |
|---|---|---|---|
| DCS/PLC | **OPC UA**（强制要求） | 火道温度、煤气流量、分烟道吸力、集气管压力、烟气残氧、氨水流量 | ≤ 30秒 |
| LIMS | **REST API / 数据库视图** | 单种煤工业分析、煤岩参数、焦炭冷/热态强度 | 每批次 |
| 皮带秤/地磅 | **OPC / Modbus TCP** | 各煤种上料量、焦炭出厂量 | 每次作业 |
| 视频监控系统 | **RTSP / GB28181** | 焦炉炉顶、地下室、皮带走廊、煤气柜区 | 实时流 |
| 化产系统 | **OPC UA** | 焦油/粗苯产量、硫铵含量、循环水温度 | ≤ 1分钟 |
| 干熄焦(CDQ) | **OPC UA** | 蒸汽产量、锅炉水位、汽包压力、发电功率 | ≤ 30秒 |
| 设备状态 | **Modbus TCP** | 电机电流、轴承温度、振动值 | ≤ 10秒 |
| ERP/进销存 | **REST API** | 煤种库存、采购价格、销售订单 | 每日 |

## 2. 接口技术规格书模板（写入合同附件，V1.1 §3.2.2）

```yaml
# 数据接口技术规范（节选）
opc_ua_server:
  protocol: "opc.tcp"
  port: 4840
  security_mode: "SignAndEncrypt"
  authentication: "Username/Password or Certificate"
  node_address_space: # 必须提供完整的节点地址空间文档
    - node_id: "ns=2;s=Furnace1.Burner.MachineSide.Temp"
      description: "1#焦炉机侧火道温度"
      data_type: "Float"
      unit: "℃"
      sampling_rate: "1000ms"  # 最低要求1秒
      # 以下为落库映射字段（AI 平台侧约定，采集→TDengine 用，见 config/dcs_tags.yaml）：
      tag_key: "fire_channel_temp"   # furnace_temp 超级表列名
      furnace_id: 1                  # 焦炉编号
      burner_side: "machine"         # machine/coke/common（炉级公共量）

  # 必须支持的历史数据读取
  history_read: true
  history_depth: "30 days minimum"

# 网络要求
network:
  redundancy: "双网卡 + 双交换机"
  bandwidth: "≥ 1Gbps"
  latency: "≤ 10ms (厂内)"
  protocol_isolation: "OT网络与IT网络物理隔离或VLAN隔离"
```

## 3. 数据治理标准（V1.1 §3.3）

| 指标 | 标准 |
|---|---|
| 数据采集覆盖率 | ≥ 95%（关键工艺参数100%） |
| 数据在线率 | ≥ 99% |
| 数据处理延迟 | ≤ 5秒（从产生到入库） |
| 数据保存周期 | 热数据7天 / 温数据6个月 / 冷数据10年 |
| 数据质量校验 | 入库前自动校验（范围检查、突变检查、缺失插值） |
| UWB定位精度 | 静态 ≤ 0.3m / 动态 ≤ 1m |

> 补充（V1.1 §4.2.6）：换向前后 2~3 分钟的温度/流量/吸力数据为脏数据，入库前打标记、建模前剔除，在 ETL 管道数据质量校验模块中实现。

## 4. DCS/MES 招标技术规格书 AI 相关条款（V1.1 §9.1，必须写入合同）

```
1. OPC UA服务器
   - 必须提供符合OPC UA规范的服务器
   - 必须开放全部工艺参数的节点地址空间
   - 必须支持历史数据读取（至少30天）
   - 必须支持订阅模式（Subscriptions）
   - 安全策略：SignAndEncrypt

2. 数据采样率
   - 关键工艺参数（温度/压力/流量）：≤ 1秒
   - 一般参数：≤ 30秒
   - 设备状态参数：≤ 10秒

3. 网络接口
   - 提供独立的数据采集网口（不与操作网混用）
   - 支持VLAN隔离
   - 提供交换机端口镜像能力（用于流量分析）

4. 冗余与高可用
   - OPC UA服务器支持冗余（主备自动切换）
   - 数据采集中断恢复后自动补传历史数据

5. 验收标准
   - 数据采集完整率 ≥ 99.9%
   - 数据延迟 ≤ 5秒（从现场到AI平台）
   - 提供不少于30天的试运行数据供验证

6. 点表交付（V1.1新增）
   - 交付完整数据库点表（点位号/中文描述/量程/工程单位/采样率）作为合同附件
   - 点表变更须书面通知并同步更新

7. LIMS电子接口（V1.1新增）
   - LIMS必须提供化验结果结构化电子接口（REST API或数据库视图）
   - 化验班数据录入流程从纸质单改为系统录入（写入化验室管理流程）
     ——自用项目最容易死在化验数据躺在纸质记录本上
   - 历史化验数据提供一次性导出（Excel/CSV）

8. AI安全边界（V1.1新增）
   - 安全联锁（集气管压力高限/煤气压力低限/烟道吸力低限等）走DCS硬联锁回路，
     不接受任何外部系统旁路
   - 外部系统（AI平台）仅可写入设定值，且DCS侧对设定值做上下限与变化速率硬钳位
   - AI平台断连时DCS自动保持最后有效设定值并报警
```

## 5. 相关数据库表结构

核心表结构（配煤方案表、焦炭质量化验表、炉温时序超级表、设备状态表）见
`data/schemas/postgresql.sql` 与 `data/schemas/tdengine.sql`，字段定义以 V1.1 §3.4 为准
（含 V1.1 新增的煤岩反射率分布直方图 `rmax_distribution`、活惰比 `active_inert_ratio`、
炼焦工艺侧字段与 `control_mode` 控制模式字段）。

2026-08-15 起新增（V1.1 修订12，§3.4.5~3.4.8）：`coal` 煤种主数据、`pdm_alarm` 设备
PdM 告警、`vision_alarm` 视觉告警、`operation_audit` 操作审计；存量库走
`data/schemas/migrations/` 编号增量迁移（机制见其 README）。

采集落库映射：OPC UA 点位 → TDengine `furnace_temp` 子表/列 由 `config/dcs_tags.yaml`
的 `tag_key` / `furnace_id` / `burner_side` 三个字段定义（子表名 =
`furnace{furnace_id}_{burner_side}`），实现见 `data/collector/opcua_client.py`
`build_tdengine_statements`；入库前范围检查上下限唯一来源是 `config/settings.yaml`
的 `quality_check.range` 段。
