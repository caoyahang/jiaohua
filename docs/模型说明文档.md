# 模型说明文档

> 摘录重组自《AI焦化厂智能化落地方案 V1.1》第四章（AI应用系统详细设计）与第五章（算法选型总表）。
> 代码实现对应 `models/` 下各子模块。

## 1. 应用一：智能配煤系统（V1.1 §4.1，第一批上线，ROI最高）

### 1.1 系统定位

输入焦炭质量要求和当前煤种库存/价格 → 输出 3 套配煤方案（成本最优/质量最稳/综合推荐）
→ 配煤师确认 → 执行 → 结果回流 → 模型自学习。

### 1.2 三模型协同架构

```
┌──────────────────────────────────────────────────────────┐
│                    智能配煤引擎                           │
├──────────────────────────────────────────────────────────┤
│  模型A：焦炭质量预测模型 (LightGBM)                      │
│  输入：配煤方案 → 输出：M25/M10/CSR/CRI预测值             │
│  作用：作为优化器的"模拟器"（代理模型）                    │
├──────────────────────────────────────────────────────────┤
│  模型B：配煤成本优化器 (遗传算法 GA)                      │
│  输入：煤种/价格/库存/质量约束 → 输出：最优配比            │
│  调用模型A作为适应度函数                                  │
├──────────────────────────────────────────────────────────┤
│  模型C：煤质-成本弹性分析 (SHAP可解释性)                  │
│  输入：当前最优解 → 输出：各煤种对成本/质量的边际贡献      │
│  作用：辅助配煤师理解和微调                                │
└──────────────────────────────────────────────────────────┘
```

### 1.3 核心算法选型（V1.1 §4.1.3）

| 环节 | 算法 | 理由 |
|---|---|---|
| 质量预测 | 冷启动：**经验配煤模型**（CBRI法/新日铁配煤法/煤岩配煤模型）；数据积累后：**LightGBM** / XGBoost | 新厂无历史数据，先用公开经验公式跑通流程；GBDT是表格数据王者、可解释、训练快、支持增量学习 |
| 配煤优化 | **遗传算法**（scikit-opt） | 处理非线性约束、多目标优化能力强 |
| 可解释性 | **SHAP值分析** | 告诉配煤师"为什么是这个配比" |
| 小样本期 | **高斯过程回归（GPR）** | 数据少时也能给出置信区间 |

### 1.4 特征工程清单（约40维，V1.1 §4.1.4修订）

- **单种煤基础指标（7维+分布特征）**：灰分(Ad)、挥发分(Vdaf)、硫分(St,d)、粘结指数(G)、胶质层厚度(Y)；
  镜质组反射率**分布直方图**（Rmax 0.5~2.0 分段占比，8~12维，V1.1修正：单值Rmax表达不了混配后的"凹口"）；
  活惰比（活性物/惰性物，煤岩定量）
- **配比特征（5维）**：各煤种配比、配比熵、最大单一煤种占比、最低占比煤种、配比方差
- **成本特征（3维）**：吨煤成本、各煤种单价、价格波动率（近30天）
- **煤岩组合特征（5维）**：活性物/惰性物含量、活惰比、流动性指数(G×Y/Ad)、镜质组丰度、壳质组含量
- **工艺特征（4维）**：装炉煤堆密度、水分(Mt)、粉碎细度(<3mm占比)、配合煤CSR预估值
- **炼焦工艺特征（5维，V1.1新增）**：实际结焦时间、机侧/焦侧平均火道温度、装炉堆密度实测值、
  熄焦方式（干熄/湿熄）、干熄率。⚠️ CSR/CRI 强依赖炼焦工艺（结焦时间20h→24h，CSR可差3~5个点），
  只喂煤质特征会把工艺波动学成噪声
- **约束特征（4维）**：各煤种库存可用天数、供应商最低采购量、运输在途量、合同锁价量

### 1.5 训练数据策略（V1.1 §4.1.6修订：经验模型冷启动）

> ⚠️ 冷启动现实：配煤比+化验数据是各厂核心商业机密，「购买/交换同行数据」基本不可行，
> 且表格数据迁移学习效果有限。投产前主线必须是**自建数据 + 经验模型**。

| 阶段 | 数据来源 | 数据量 | 方法 |
|---|---|---|---|
| 投产前（0~6月） | ① 经验配煤模型打底（CBRI法/新日铁配煤法/鞍山热能院煤岩配煤模型，公开文献）作为冷启动"模型A" ② 40kg/200kg试验焦炉DOE系统试验（正交/均匀设计） ③ 20~30个拟采购煤种全分析数据库（含煤岩反射率分布） | 经验模型 + 60~100炉DOE | 经验公式 + DOE数据拟合修正 |
| 试生产（6~12月） | 本厂实际配煤+化验数据（含工艺侧特征） | 200~500组 | LightGBM全量训练，每周增量；小焦炉数据需先标定与大炉的CSR/CRI系统偏差 |
| 达产期（12月+） | 本厂积累数据 + 煤源变化适应 | 500~2000组 | 在线学习 + 自动重训 |

### 1.6 增量学习机制（V1.1 §4.1.7）

每次出焦化验结果回来 → 对比预测值 → 误差超阈值入缓冲区 → 缓冲满 50 条触发增量训练
（LightGBM `init_model` 热启动 + 小学习率防遗忘）。实现见 `models/quality_predictor/`。

## 2. 应用二：焦炉AI智能加热控制（V1.1 §4.2）

### 2.1 三阶段控制模式（V1.1 §4.2.2）

| 模式 | 说明 | 适用阶段 |
|---|---|---|
| Manual（手动） | 完全人工控制，DCS自主操作 | 烘炉期、异常工况 |
| Shadow（影子） | AI实时计算但不下发，仅显示推荐值，与人工操作对比 | 试生产前3个月 |
| Auto（自动） | AI计算结果自动下发DCS执行，人工可一键切回手动 | 验证通过后 |

### 2.2 算法选型（V1.1 §4.2.3）

| 环节 | 算法 | 理由 |
|---|---|---|
| 火道温度预测 | **LSTM / Transformer** | 时序依赖强，需记忆长期趋势 |
| 火落时间预测 | **CNN + LSTM（时空特征）** | 结合看火孔图像+温度曲线 |
| 最优控制量求解 | **模型预测控制（MPC）** | 工业控制标准方法，有约束处理能力 |
| 超参数优化 | **贝叶斯优化** | 自动调参，减少人工干预 |
| 异常检测 | **自编码器（AutoEncoder）** | 无监督，发现未知故障模式 |

### 2.3 控制架构（V1.1 §4.2.4）

1. **状态预估**：输入过去60min火道温度序列、煤气流量、吸力、残氧 → LSTM预估未来30min温度曲线
2. **优化求解**（每2个交换周期一次）：目标 `min Σ(预测温度-目标温度)² + λ·煤气消耗量`，
   约束为温度上下限/煤气流量限值/吸力限值，求解器用粒子群优化(PSO)/梯度下降
3. **下发执行**：煤气流量设定值、分烟道吸力设定值 → DCS → 执行器；空气过剩系数建议值供调火工参考
4. **反馈校正**：实际温度 vs 预测温度 → 模型误差补偿 → 下次预测修正

### 2.4 安全设计与热工K系数（V1.1 §4.2.6新增）

**安全联锁硬隔离（红线，同步写入第九章DCS招标条款）**

- 集气管压力高限、煤气压力低限、烟道吸力低限等安全联锁**永远走DCS硬联锁回路**，AI通道物理上无权触碰
- AI只输出设定值（setpoint）；设定值上下限与变化速率在 **DCS侧硬钳位**，不依赖AI自律
- AI服务宕机/网络中断时，DCS自动保持最后有效设定值并报警，不依赖AI心跳
- 「一键切手动」为硬切换，不经过AI系统软件层

**换向期数据剔除**：换向前后2~3分钟的温度/流量/吸力数据为脏数据，入库前打标记、建模前剔除（ETL管道实现）。

**热工K系数定义（运营总览与加热控制统一考核口径）**

| 系数 | 定义 | 用途 |
|---|---|---|
| K均 | 直行温度均匀系数 =（机侧+焦侧合格火道数）/ 总测量火道数 | 加热控制核心KPI |
| K安 | 直行温度安定系数（相邻班次标准温度波动合格率） | 热工稳定性考核 |
| K1 | 推焦计划系数（计划结焦时间与规定结焦时间符合率） | 排产计划质量 |
| K2 | 推焦执行系数（实际推焦时间与计划时间符合率） | 执行质量 |
| K3 | = K1 × K2，推焦总系数 | 排产核心KPI（见4.5） |

数据来源：直行温度测量记录、推焦电流记录、推焦计划表——依赖数据底座先行落地。

## 3. 应用三：设备预测性维护 PdM（V1.1 §4.3，两级化）

### 3.1 监控对象优先级（V1.1 §4.3.1）

| 优先级 | 设备 | 监测参数 | 故障后果 |
|---|---|---|---|
| P0 | 推焦车走行机构 | 振动、电流、温度 | 停产 |
| P0 | 拦焦车导焦栅 | 振动、位移 | 停产+安全隐患 |
| P0 | 干熄焦循环风机 | 振动频谱、轴承温度 | CDQ停产+红焦落地 |
| P1 | 装煤车螺旋给料 | 电流、转速 | 装煤不均 |
| P1 | 焦炉煤气鼓风机 | 振动、轴承温度、流量 | 煤气系统波动 |
| P1 | 化产离心泵 | 振动、密封温度 | 泄漏风险 |
| P2 | 皮带输送机 | 振动、皮带跑偏 | 断料 |

### 3.2 两级预警体系（V1.1 §4.3.2修订：RUL后置）

> ⚠️ 焦化厂故障样本极少（单台设备年故障个位数），LSTM退化模型/RUL 在 2~3 年内没有足够样本，
> 不做承诺式开发。

- **第一级：实时异常检测（毫秒级）**——孤立森林发现突发异常（如振动突然飙升），输出 WARNING
- **第二级：趋势预测 + ISO 10816 分级（每天一次）**——LSTM 预测未来7天振动趋势，
  结合分级阈值判定 WARNING（建议安排检修）/ DANGER（建议尽快停机检查）
- **后置项**：第三级 RUL 剩余寿命估算（LSTM+贝叶斯 / Wiener退化过程），
  积累 2~3 年故障样本、有效样本 ≥50 例后再立项

### 3.3 振动分析标准（参考 ISO 10816，V1.1 §4.3.3）

| 振动速度(mm/s) | 等级 | 建议动作 |
|---|---|---|
| < 2.8 | 良好 | 正常运行 |
| 2.8 ~ 7.1 | 注意 | 加强监测频率 |
| 7.1 ~ 18 | 不合格 | 计划检修 |
| > 18 | 危险 | 立即停机 |

## 5. 应用五：智能排产与调度（V1.1 §4.5）

- 求解器：Google OR-Tools **CP-SAT** 约束规划，目标为最小化延迟并最大化 K3
- 输入：客户订单（焦炭品种/数量/交期）、各焦炉状态（结焦时间/炉温）、检修计划
- 输出：每座焦炉推焦计划（具体到每炉推焦时间）、配煤方案联动、化产回收排程
- 约束：K3 ≥ 0.95；结焦时间不短于设计最小值；同一炭化室连续推焦间隔均匀；检修窗口避让；化产回收能力匹配
- K系数口径（与 §2.4 统一）：K1 计划结焦时间符合率、K2 实际推焦时间符合率、K3 = K1×K2

## 6. 应用六：化产回收AI优化（二期，V1.1 §4.6新增）

定位：化产数据规整、波动频繁、节能省药剂见效快，建模难度低于加热控制，是被低估的高性价比场景。

| 场景 | 方法 | 收益点 |
|---|---|---|
| 洗苯塔洗油温度/流量优化 | 回归模型 + 规则寻优 | 提高粗苯回收率、降低洗油消耗 |
| 饱和器母液酸度/温度控制 | 时序预测 + 设定值推荐 | 硫铵质量稳定、减少晶比波动 |
| 鼓冷系统（初冷器温度、鼓风机运行优化） | 多变量优化 | 电耗降低、煤气净化稳定 |
| 脱硫液循环量/再生空气量寻优 | 模型预测 + 寻优 | 保脱硫效率、降蒸汽电耗 |

接入条件：化产系统 OPC UA 数据积累 ≥3 个月后启动（接口见《数据接口规范》）。

### 7.2 算法选型决策树（V1.1 §5.2）

```
数据是什么类型？
├─ 表格数据（配煤、化验、成本）
│   ├─ 数据量 < 200条 → 高斯过程回归(GPR) / 贝叶斯
│   ├─ 数据量 200~10000条 → LightGBM / XGBoost
│   └─ 数据量 > 10000条 → LightGBM + 特征选择
├─ 时序数据（温度、流量、振动）
│   ├─ 需要预测未来值 → LSTM / TCN / Prophet
│   ├─ 需要检测异常 → 孤立森林 / AutoEncoder
│   ├─ 需要控制决策 → MPC + LSTM/Transformer
│   └─ 需要剩余寿命 → LSTM + 退化模型
├─ 图像/视频数据
│   ├─ 目标检测(人/火/烟) → YOLOv8
│   ├─ 像素分割(块度/泄漏) → Mask R-CNN
│   ├─ 表计读数 → YOLOv8 + OCR
│   └─ 火焰分析 → ResNet + 分类头
└─ 优化决策问题
    ├─ 连续变量优化(配比/流量) → 遗传算法/粒子群
    ├─ 离散调度问题(排产/路径) → CP-SAT / 遗传算法
    └─ 多目标权衡(成本vs质量) → NSGA-II / 帕累托优化
```

### 7.3 为什么不推荐某些"热门"算法（V1.1 §5.3）

| 不推荐算法 | 原因 | 替代方案 |
|---|---|---|
| 大模型(LLM) | 焦化是数值控制场景，LLM不擅长精确回归；数据敏感不能上云；推理成本高 | 规则引擎+知识图谱 |
| 深度神经网络(DNN) | 表格数据上不如GBDT，调参难，解释性差 | LightGBM + SHAP |
| SVM | 大数据量训练极慢，效果不如GBDT | LightGBM |
| 强化学习(RL) | 需要大量试错，焦化容错率低，烧坏炉砖代价巨大 | 先建数字孪生再考虑 |
| GAN | 工业场景数据增强收益有限，训练不稳定 | 传统数据增强+迁移学习 |
